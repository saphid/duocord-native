## Route construction and safe metadata

[DiscordEndpoint.descriptor](../Discord/Routes.swift#L29) is the sole Discord-authenticated route constructor. One closed enum defines method, encoded path, sanitized template and the existing rate-bucket identity together. Fixed segments and typed parameters produce path/template together; templates are never inferred by replacing numeric-looking pieces of a raw URL. `ChannelID`, `MessageID`, `UserID` and `GuildID` have no implicit interchange. The legacy `Snowflake` models/protocol remain compatible; `DiscordREST` explicitly converts at the boundary. These types establish resource kind only, **never permission, existence, channel kind or ownership**. No whole-model migration, generator or generic retry framework was added.

[DiscordREST.raw/request/get](../Discord/REST.swift#L637) accept only endpoints. Request method/path and admission identity come from the descriptor. Existing per-route bucket names and major identity are preserved, including the historical guild+user member key, thread/search families, pin read/fallback sharing, and server bucket + major mapping. A cross-route production-wire test verifies a shared server bucket queues the same channel while a different channel remains independent. Bucket identities contain resource IDs for admission only; they are never logged.

`Emoji.reactionPathSegment` and route segments share encodeURIComponent-compatible escaping (`-_.!~*'()` remain unescaped; `/`, `:`, `%`, query delimiters and Unicode encode exactly once). Pin `before` is an opaque `pinned_at`, not a Snowflake; its `+` is strictly escaped as `%2B`. Archived-thread cursors retain the existing URLComponents behavior and exact value; this slice does not change their query encoding. Search query/content, IDs in queries and payloads stay outside diagnostics.

`DiscordREST.lastRequestDiagnostic` stores one compact in-memory value: method, registry template, HTTP status, numeric Discord code when decodable, request outcome (confirmed HTTP response, refused write, proven not dispatched, unknown write, read failure), and typed source (HTTP response, transport or operation error). Calls cancelled before request admission do not replace this value. It is the last completed request's metadata, not an ordered trace or proof that an AppModel operation committed. Decode failures log only method-independent sanitized route templates, with no decoder descriptions/coding keys. Rate-limit messages use templates. Timeline HTTP failure log sites emit constant event names; they no longer print arbitrary localized transport/server errors. This leaves their state machines and user feedback unchanged. `OperationRefusal.diagnostic` adds refresh outcome and typed attribution provenance from the proven decision. Full reevaluation, original HTTP/code/message and retained payload stay available in the existing in-memory refusal record. A 5xx is unknown, never a definite refusal. There is no telemetry service, durable diagnostic log, request dump, raw URL, signed URL, filename/data, emoji, credential, token segment, nonce or message/reply text in these safe values.

[RouteContractTests](../Tests/RouteContractTests.swift) checks independently literal methods/encoded paths for every entry point, actual request-to-descriptor equality, migrated operation method/templates, token-like and ID-like/emoji segments, unknown codes/original error preservation, decode sanitization, relationship variants, opaque pin cursors, pins fallback, signed-upload isolation and shared-bucket admission. [Compiler probes](typechecks/route-positive.swift) typecheck production `Discord/Routes.swift` directly: the positive fixture exits 0; each [wrong channel](typechecks/route-wrong-channel.swift), [wrong message](typechecks/route-wrong-message.swift), [wrong guild](typechecks/route-wrong-guild.swift) and [wrong user](typechecks/route-wrong-user.swift) fixture must exit nonzero with a resource-kind mismatch. Negative fixtures are deliberately excluded from the app/test targets. Exact Xcode 27.2 compiler commands/results are in the report; a compile failure for an unrelated reason is not accepted as proof.

## Shared failures and policies

These are **declared client categories**, not an exhaustive Discord error catalog. All rows retain unknown codes and uncoded HTTP errors safely. A malformed code must not discard a valid original message, and vice versa. Request diagnostics project only numeric code/status; the original error remains in memory.

| Key | Known or declared failures | Safe fallback |
| --- | --- | --- |
| F | 401/session-ended; 429/rate-limited; other 4xx refusal; 5xx; transport/cancellation; decoding/malformed response; unknown numeric code | Preserve original error and account fence. No automatic generic retry. A lost response/5xx does not prove a write failed. |
| C | F plus 10003 Unknown Channel, 50001 Missing Access, 50013 Missing Permissions where the server supplies them | Code alone cannot prove View Channel is missing; never evict readable history from 50001 alone. |
| M | C plus 10008 Unknown Message; send/DM may supply 50007 Cannot Message User | Unknown ownership/state/account rules remain unknown; retain content and recoverable state. |
| T | C/M plus 50083/160005 thread state; reply send may supply 160002 | Bounded operation-aware attribution; no write replay. Dedicated membership 404/10007 alone establishes absent self membership. |
| A | F; account privacy, relationship/state, target or field validation can refuse; 50007 may explain DM delivery | Account-specific behavior is server enforced. Do not borrow guild permission requirements or claim an exhaustive numeric map. |

| Policy | Outcome, retry, reconciliation and deadline |
| --- | --- |
| R | Reads: up to four GET attempts **only after HTTP 429**, with bucket/global admission and server wait. No network/5xx generic retry. URLSession request timeout is 20 s; queue/bucket/429 time has no universal total action deadline. Cancellation is honored. Consumers retain cursor/scope/session/revision authority; response absence is not proof of server absence. |
| FRESH | Capability reads are R inside one coalesced **4 s total refresh budget**, including admission/429, bounded further by a send's remaining 45 s action budget. Late commits require unchanged account/login/store epoch + entity generations/tombstones. Incomplete/failed/expired refresh preserves the original refusal and unknown facts. |
| SEND | Both send overloads share one **45 s total attempt budget** (default `SendAttempt`), including admission, reservation, transfer, final POST and attribution. Final POST marks dispatch; proven preconnection/before-dispatch failure differs from unknown after dispatch. No automatic POST replay. Retain original nonce/payload/files and reconcile unknown outcomes with matching gateway or bounded permitted history. Empty history is not negative proof. Only explicit safe retry may POST again. Server nonce deduplication is unverified. |
| MUTATE | Edit/delete/reaction/pin/thread actions recheck shared capability/ownership/payload contracts at actual dispatch, retaining existing FIFO/coalescing and gateway authority. No transport write retry. Confirmed gateway/HTTP beats a late failure. Refusal attribution uses FRESH; ambiguous reaction/pin/send readback remains specific to existing state machines, not a general retry. The normal request timeout is 20 s; other queues/admission lack an overall deadline. |
| READ-STATE | Existing account read queue captures exact boundaries/manual/count payload; stale session/versions/arrival counters cannot publish old success. Single ACK and deprecated guild ACK never retry automatically. **Existing explicit bulk-read controller exception:** chunks of at most 100 captured positive, nonmanual boundaries retry a refused 429 up to 3 times, only for retry-after ≤30 s. This is in `App/ReadActions.swift`, not a REST/generic retry; uncertain network writes are not replayed. No total overall action deadline. |
| ACCOUNT | Existing confirmed account writes retain their own FIFO, gateway/version/session and navigation fences; no guild capability migration or universal unknown-write UI is claimed. No transport retry; explicit user retry uses current state. Relationship/name/DM/privacy refusals remain recoverable. Request timeout 20 s; queue/admission has no overall deadline. |

## Payload, migration and unresolved semantics

Shared operation evaluation now covers view/send/reply/upload, own edit, ownership-aware delete, new/existing/remove-own reactions, list/pin/unpin and existing thread actions. UI and dispatch share `DiscordOperation`, `OperationFacts`, the resolver and ThreadCapabilities. Allowed/denied/unknown remain separate. Missing guild/member/parent/membership metadata cannot manufacture all permissions. Actual retained reply/file features matter; plain text can remain eligible without AttachFiles. Timeout/cooldown uses current account/channel facts and time, with explicit refresh preserving drafts. Capability refresh is read-only and never automatically sends.

Account read state, notification preferences, friend/relationship/DM, settings protobuf, search, mentions and advisory typing retain their existing action-specific policies. A route descriptor migration does **not** mean those actions now use guild permission resolution or the shared OperationRefusal lifecycle. Their version/session/gateway/navigation contracts remain separate. No universal action deadline or universal ambiguous-account-write recovery was added.

Native `MessagePayloadFeatures` describes reply/file/embed/poll permission needs, not an entitlement oracle. Production message sends construct text/reply/files, not new poll/embed authoring. Local empty-send checks, reply/ping rules, attachment reservation integrity, URL safety, and exact upload bytes are tested. **No universal 2,000-character bot limit was imported.** Current human-account message length, Unicode counting unit, upload size/file count, Nitro/guild entitlements and custom/external emoji access are not fully known or locally enforced by a new numeric limit. Discord enforces them; preserve coded/field errors and retained drafts. The current error parser preserves status/code/message, not the full nested validation body. New local numeric boundaries require account evidence first. Positive mocks accepting large Unicode content cannot prove live entitlement limits.

U evidence remains a hypothesis for voice/stage Connect, pin history/channel-kind constraints, archived own-delete/reaction semantics, automatic thread reopening/creator exceptions, private-thread timeout behavior and human slowmode exemptions. Known native facts and resolver provenance may explain an action refusal; unknown bot/account hypotheses cannot become a proven attribution. Dedicated guild/DM permissions, server enforcement, and a typed resource ID are separate concepts.

Current capability race evidence covers channel/overwrite, discovered parent, thread membership/state, roles, member/owner changes, deletions, account switch and READY epoch replacement. Not every redundant gateway member-bearing shape is held in a race test. No process-death send persistence, cross-session replay, live nonce-deduplication guarantee, physical-device or layout proof is claimed. The parent owns fresh independent review, broad full suite and any later publication.
